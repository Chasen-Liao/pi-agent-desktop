# Pi Agent Desktop v0.10.0

发布日期：2026-10-11

## 升级

- **Pi SDK 升级至 1.1.0**：`@earendil-works/pi-ai`、`pi-coding-agent`、`pi-mcp` 从 0.99.1 跨大版本升到 1.1.0。依次跨越 1.0.0 / 1.0.x / 1.1.0，带来 Codemode 提示词降约 40% token、codemode 图像生成、MCP 项目级 override、`pi.registerToolRenderer()`、MCP OAuth 全链路可取消与请求超时、工具执行时长 `durationMs`、Claude Haiku 5.5 等上游改进。
- **漏洞修复随上游落地**：1.1.0 钉 `brace-expansion@5.0.12`，修复上游标记的 GHSA-q2hr-2g5m-vwhr 等漏洞。

## 修复

- **Azure Provider 改名适配**：上游 1.0.3 将 provider id 从 `azure-openai-responses` 改为 `azure`，模型配置界面的 Azure 条目图标 key 同步更新。既有配置需要手动迁移：`auth.json`、`models.json.providers` 中的 provider key，以及 `settings.json` 的 `defaultProvider`、`enabledModels` 中的 provider 模式、`modelThinkingLevels` 中的 provider/model key 都改用 `azure`。API id `azure-openai-responses` 与环境变量 `AZURE_OPENAI_*` 不变；旧 Azure 会话恢复时可能回退到其他模型，原提示词缓存不能复用，请确认当前模型后再继续。
- **MCP 凭据边界**：拒绝项目 `mcp.json` 直接引用模型 provider 凭据；全局 `auth.provider` 必须使用 HTTPS（仅 loopback HTTP 例外）。配置加载与保存均执行检查。
- **MCP 项目覆盖**：项目只修改 `enabled`、`exposure`、`toolExposure` 时保留全局连接和认证配置；配置界面与运行时使用同一合并结果，原生 `/mcp` 保留覆盖文件来源。

## 兼容性与已知限制

- 本次为跨 1.0 大版本升级，除 Azure 图标外，还适配了新增 MCP 认证与项目覆盖规则。类型检查不能单独证明运行时兼容，相关边界已用隔离配置和真实 SDK 回归测试验证。详见 [docs/research/pi-core-upgrade-2026-10-11.md](../research/pi-core-upgrade-2026-10-11.md)。
- 未做正式三平台打包验证；Windows / macOS / Linux 安装包由 CI 产出。
- Windows / macOS / Linux 安装包均未代码签名。Windows 可能出现 SmartScreen 提示；macOS 未公证，可能出现 Gatekeeper 提示；Linux 自动更新经 `dpkg` / `apt` 安装未签名 `.deb`，需要 root 授权。
- 与终端 CLI 同时运行仍共享 `~/.pi/agent` 目录；同一 session 两端同时写入仍不受支持。
