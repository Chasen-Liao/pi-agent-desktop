Pi Agent · 记忆架构

会话级 JSONL 流水账 + 项目级 SQLite 长期记忆，两层互补。LTM 经 MemoryService 门面对外统一暴露（工具 / HTTP API / 自动观察），best-effort 不阻塞对话。

L1 会话 JSONL（episodic）
L2 长期记忆 LTM
存储 / 后端
机制 / 边界

01 · 两层记忆模型

L1 逐字记录“这次会话发生过什么”；L2 可检索索引“这个项目长期该记住什么”。通过 sessionId / projectId 关联，互不干扰。

L1 · 会话 JSONL 未改动
每个会话一个 .jsonl，热写（AgentSession）与冷读（session-reader）双路径；Fork/Branch 是记忆分裂策略，compact 是唯一的“遗忘”机制。
L2 · 长期记忆 LTM v0.7.19
项目级 SQLite（~/.pi/agent/memory/ltm.sqlite），跨会话持久。六类 memories + 自动 observations，FTS5 全文检索。

02 · LTM 内部分层

所有入口只调用 MemoryService，绝不直接碰 SQL；启用与禁用统一由服务门面处理。

入口 ● Agent 工具 + HTTP 3 工具 · 5 路由
memory_save / memory_recall / memory_forget（plan 模式只留 recall）· /api/memory/{remember,recall,forget,health,stats}
MemoryService ● 门面（单例）
由 cwd 算 projectId、校验输入、resolve backend；单例挂 globalThis.__piLtmService（HMR 安全）
MemoryBackend ● 统一接口
remember / recall / observe / forget / health；由启用态 SQLite 或禁用态 NoopMemoryBackend 实现
SqliteBackend 启用
node:sqlite · FTS5 · WAL + busy_timeout · 事务原子 · 60s 去重
NoopMemoryBackend 禁用
LTM 禁用时使用；不访问磁盘，observe 静默返回去重结果
SQLite ● ltm.sqlite
memories + observations 两表 + 各自 FTS5 虚表

03 · 数据模型

memories 有版本链（supersede 靠 is_latest + parent_id）；observations 是自动留档。

memories

字段说明
idmem_<ts>_<rand>
project_id项目隔离，有索引
typepattern · preference · architecture · bug · workflow · fact
title / content标题 / 正文（≥8000 截断）
concepts_json · files_json可选结构化
is_latest · parent_id版本链：最新可见，旧版指向 parent
created_at · updated_atISO-8601

observations

字段说明
idobs_<ts>_<rand>
project_id项目隔离，有索引
session_id来源会话
kindagent_end · pre_compact
title / narrative标题 / 正文（≥4000 截断）
source_json可选原始片段
created_atISO-8601

FTS：memories_fts(title,content) · observations_fts(title,narrative)；recall 分表 LIMIT 后合并按 FTS 分数排序。

04 · 读写路径

三条写（一显式 + 二自动零-LLM）+ 一条读。

显式写 memory_save

工具调用 → service → remember → supersede 检查（jaccard>0.7 置旧版非 latest）→ 事务内写新行 + FTS。ask 模式走确认。

自动写 agent_end observe

agent 循环结束（rpc-manager 的 agent_end 事件）→ 零-LLM 合成 User:/Assistant: 摘要 → 60s 内同 session+kind+title 去重。

自动写 pre_compact observe

compact 触发前 → 保留将被打包压缩的分支/消息快照，避免“遗忘”后 context 视图丢信号。

读 memory_recall

工具查询 → FTS 检索 memories（主）+ observations（次）→ 合并排序 → 返回紧凑 hits；模型自主决定使用，不自动注入 system prompt。

05 · 关键机制

本会话修复加固过的边界语义。

projectId

规范化 cwd（Win 小写）→ sha256 取前 16 位 → proj_…。目录移动 = 新项目（v1 已知取舍）。

supersede 版本链

新行 parent_id 指向旧 latest，旧版 is_latest=0。UPDATE + INSERT 在同一事务（崩溃窗口不丢）。

observe 去重

60s 窗口内同 project+session+kind+title 返回 {deduplicated:true}，不重复插入。

单例 + 失败缓存

__piLtmService 抗 HMR；构造失败缓存 30s（TTL 后重试一次）；disabled 用 NoopBackend 不碰磁盘。

config 热更新

serviceKey 覆盖 dbPath、enabled 与 observe 开关（JSON 编码），配置变化即重建单例。

权限语义

plan 只读：工具列表剔除 memory_save/forget；ask：memory_save/forget 走确认（与 bash/write/edit 同级）。

07 · 设计边界

best-effort 永不阻塞
observe 失败只 log 并吞掉；对话 / compact / 工具 UX 不受 LTM 影响。禁用 LTM 时工具与 API 返回结构化 disabled 文案。
v1 明确非目标
无向量检索、无自动上下文注入、无记忆管理 UI、不把 JSONL 当 LTM 源。
颜色遵循 dataviz 参考色板（分类色固定顺序）；深色模式自动。组件目录：lib/ltm（服务与后端）· app/api/memory（路由）· lib/desktop-ltm-extension.ts（工具注册）。
