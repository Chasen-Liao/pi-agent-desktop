# Before writing page code

Inspect the selected reference and prepared assets. Add brief, concrete notes to the
existing pre-implementation checklist; reuse asset mappings already recorded.

1. **Layout:** identify region order, column proportions, shared alignment edges,
   and major gaps at the target viewport. Choose the grid or flex structure that
   preserves these relationships.
2. **Visual hierarchy:** identify heading line breaks, heading/body size ratios,
   dominant colors, and repeated component styling. Record observable properties
   rather than mood words such as "modern."
3. **Assets:** check the prepared file-to-slot mapping, visible crop, and image fit
   against the reference. For the hero, distinguish a background behind live text
   from a separate image beside it; preserve that relationship, subject scale, and
   focal position. Do not turn a background composition into a side-by-side image card.
   Reuse those files; return an incorrect or missing asset
   to the existing repair step.

Follow the skill's evidence hierarchy. Use brief copy when supplied; otherwise
preserve readable supplied-screenshot text. Generated mockup wording is only a
layout cue. Mark estimated dimensions as approximate.

Once the checklist is complete, begin implementation. This check requires no separate
report, new reference generation, or additional user-confirmation round.
